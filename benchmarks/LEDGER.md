# Session ledger

`pnpm run ledger --host claude-code|codex|kilo --input PATH [--outcomes FILE --candidate ARM --baseline ARM] [--output FILE]` reads finished sessions in each host's own record format: Claude Code JSONL transcripts (grouped by session id, so subagent files join their parent), Codex rollout JSONL, and Kilo/OpenCode `kilo.db` (opened immutable). It never runs a recorded command and prints no path, prompt, command or response text.

Per session it reports host-reported usage per request (uncached input, cache read, cache write, output including reasoning, reasoning, cost), the first request's input, call classes (Osnova, search, discovery, read, edit, verify, shell, other), search-only requests and repeated search-only requests, identifier searches, searches for a name an earlier successful Osnova result already printed, denials, tool errors by class and per Osnova tool, and stop-hook settle continuations. A field a host does not report stays `null` and is counted as missing, never as zero. Codex input is split into cached and uncached parts from its total; Codex reports no cache writes. Kilo output excludes reasoning, so the ledger adds it.

With an outcomes file (`{"<session key>": {"task", "arm", "correct"}}`, keyed by Claude session id or by the file path relative to `--input`), the comparison's primary figures are cost, time and tokens per correct session, counting spend on failed sessions. Paired deltas cover tasks both arms solved; every other pair is counted as excluded. Request and call counts explain a result; they are not savings.
